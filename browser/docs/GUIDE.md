# 抖音下载浏览器 · 目录说明

双击 **`start-browser.bat`** 就能用（起本地服务 + 自动开浏览器，地址 `http://127.0.0.1:8723/`）。

## 文件夹都是干什么的

| 目录 | 里面是什么 | 能删吗 |
| --- | --- | --- |
| `src/` | 全部代码。`server.py` 是本地服务，`scanner.py` 生成索引，`watcher.py` 监听下载目录（新作品自动收录），`download_db.py` 是下载记录小库，`paths.py` 是**所有路径的唯一来源**，`web/` 是网页 | 不能 |
| `tools/` | 日常会用到的独立脚本：清缓存、恢复备份、黑名单 | 不能 |
| `tools/legacy/` | 早期一次性脚本（补 SEC_UID、迁大小号、导报表），留档备用 | 舍不得就留着 |
| `data/` | `user_data.json` = **你的标注（唯一不可再生）**；`data.json` = 扫描索引（可重生成） | `data.json` 可删（重扫即回），**`user_data.json` 绝不能删** |
| `cache/` | 缩略图 / 转码 / 封面。删了会按需重建 | 可以，但 `cover_cache`（封面）**别删** |
| `backup/` | `user_data.json` 的自动备份（3 分钟一份，留 200 份） | 建议留着 |
| `export/` | SEC_UID 导出 txt、下载/收藏汇总表（补 SEC_UID 的脚本读这里） | 可以，表别删 |
| `docs/` | `README.md` 使用说明 · `PROJECT.md` 开发文档 · `HANDOVER.md` 交接上下文 | 可以 |

## 常见事怎么办

- **界面想改，但说不上来是哪儿** → 顶栏点 **✏️ 标注**（也可以直接开 `http://127.0.0.1:8723/annotate.html`），打开「标注台」：左边就是网页本身（能点能滚），右边写意见。
  · **三步**：① 顶部选工具（框选最常用）→ ② 在左边页面上拖一下，出现 ①②③ 编号 → ③ 右边每条写一句「想变成什么样」，点 **💾 保存给我**，然后跟我说一声「存好了」。
  · 存到哪：`data\标注\界面意见_<时间>.md`（同名 `.json` 是结构化明细）。不想保存就点「📋 复制清单」粘给我，或者「⬇ 下载 .md」把文件拖进对话。
  · **三条技巧**：① 框比写字快，不用描述"第三行第二个"；② 写「想变成什么样」，别写"看着别扭"（「② 想跟③ 一样高」比「② 有点怪」有用十倍）；③ 一次框完，编号连着，我按顺序改。
  · 每条会自动认出是「哪一块」（作者名 / 数据条 / 标签卡 / 某个作品卡…）并记下对应的 CSS 选择器，所以我不需要猜你框的是什么。想标「把这个挪到那儿」就用 **↗ 箭头**；想圈不规则的地方用 **✏ 画笔**；想直接写一句话用 **A 文字**。
  · 左边比平常窗口窄一截（右边占了 336px），想按平常的排版看，点右上角 **「收起 ›」** 把意见栏收掉，改完再点「展开意见栏」。
  · 兜底：不开这个页面也行——微信/QQ 截图（`Alt+A` / `Ctrl+Alt+A`）直接在图上画框写字，`Ctrl+V` 粘进对话，我一样看得懂。
- **这次到底下了什么** → 侧边栏「功能」→ **🆕 新下载**：只列最近下载下来的文件，不是全部历史。
  · 默认「今天」（本地 0 点以后落盘的），上面能切 **近 3 天 / 近 7 天 / 近 30 天**；判断依据是文件写入时间 ≈ 下载完成时间。
  · **一位作者一个气泡**：每位作者的全部作品被一个浅灰色圆角气泡包在一起，气泡上方一行写「作者名 + 等级 / 更新频率 / 状态 / 标签」，点这行进他的详情页。
  · 气泡里**优先横向填满**：能放几张就放几张（窗口越宽、收掉左边栏后能放得更多），放不下的换到下一行。作品只有一两个的作者，气泡会自动收窄，几个小气泡并排挨在一起，不留大片空白。
  · **点左上角「«」收起侧边栏**：左边列表会自动多排一列把宽度用满，右边播放区也会跟着变宽，不会留一条空。
  · 作者名太长会显示成「名字…」，鼠标悬停能看全；标签太多时后面会收成「＋N」，悬停能看到被藏起来的标签。
  · 页面是左右两半：**左边缩略图网格，右边一个常驻的播放区** —— 点左边任意一张就在右边播，不跳新标签、也不弹窗盖住列表。
  · 右边从上到下就两块：**画面** + **下面两行字** ——
    · 第一行：**作者名 + 等级 / 更新频率 / 标签**（徽章颜色跟侧边栏一致，没标注过的写「未标注」）+ 第几个 + `›`；整行可点，进他的详情页。
    · 第二行：**发布时间 · 作品描述**（最多两行，完整文字在鼠标提示里）+ `↗` 原文件。
    · 没有左右翻页按钮、没有头像 —— 翻页按键盘 `←` `→`，或者直接点左边另一张卡。
  · **图文作品有好几张图**时，画面下方会并排列出一排小图，点哪张就看哪张（当前那张是粉色框）。
  · **点大图 = 原地放大，再点一下缩小**：图会按原始尺寸铺开、在框里滚动看细节，播放区那个框大小完全不变 —— 不是全屏、也不会盖住左边列表。
  · 翻页：按键盘 `←` `→`（或点左边另一张卡），翻的是这个作者这次下的全部文件；正在播的那张卡在左边有粉色边框。
  · 一个作品的几张图会摊平成一串，翻页就是一张张过（卡片右下角的小数字 = 共几张）；视频浏览器解不了时会自动转 H.264，转一次以后秒开。
  · 宽度固定 **420px**（窗口窄于 1280 时 340px），画面区高度也定死了 —— 换个视频、翻一张图，播放器大小都不会变，左边网格也不会跟着重排。横屏视频两侧会留点黑边，这是故意的：宁可有一点黑边，也别让版面来回跳。
  · 一个图文作品会落好几张图（`_1` … `_9.jpeg`），这里合并成一张卡，右下角小数字是「共几张」，左下角写「图文」。
  · 右上角 **🔄 刷新** = 重新读一遍下载记录库。刚下完进来是空的，等 5 秒再点一次就有了（服务端要等下载安静下来才扫）。
- **想看现在的东西是不是好的** → 打开网页，侧边栏「分类」里点「全部作者」，能看到 **1700 多个**作者就正常（数字随下载增减，2026-10-31 是 1716）。
- **以后又下载了新作品，怎么让它出现在网页里** → 什么都不用做。服务在后台**监听**下载目录（不是定时去翻），下载器一落盘系统就通知我们，等它安静 5 秒后自动扫一遍（**只扫变了的文件夹，1~2 秒**）。没下载的时候它一次硬盘 IO 都不发，E: 机械盘可以正常休眠。网页上会弹一句「后台已更新（N 个作者有新内容）」，点右上角 ⟳ 刷新就能看到。
  · 为什么要等 5 秒：下载器一边下一边写，正是「文件大小还在变」的时候，抢着扫会把半截文件的大小记进下载记录库。等它停手 5 秒再扫，记下来的都是完整文件。万一某个作者一直在下（同一个号几十条），最多攒 120 秒也会先扫一批。
  · **服务没开的时候下的东西**：那时没人监听、事件就没了，所以启动后 30 秒会补查一次（列一次根目录比 mtime，0.09 秒），把漏掉的补上。
  · 万一监听起不来（比如 E: 盘掉线），启动日志会写「监听没起来 → 退回每 5 分钟查一次」，功能不受影响，只是回到老的轮询方式；盘恢复后它会自己重连。
  · 手动点 ⟳ 也是增量扫描，同样 1~2 秒；想彻底重扫一遍时，在 `src` 目录跑 `python scanner.py --full`（约 8 分钟，不常用）。
  · 增量靠「文件夹改动时间」判断，所以**新数据是加进来的，不会覆盖旧数据**：旧作品原样保留，`data.json` 只是索引、可随时重生成；你的标注（星标/标签/状态/封面/备注）都在 `data\user_data.json`，永远不动。
- **详情页作者卡右下角那个「气泡」里的数怎么看** → 从左到右：`作品 554（v552 p2）` = 本地作品数（v=视频条数、p=图文条数，两者相加就是作品数）→ `抖音 33 发布 2025-10-30` = 抖音上的作品数，后面那个日期是**抖音上最新一条作品的发布时间**（拿不到发布时间时写「获取 + 取数时间」）→ `最后下载 1 年前 2025-10-27` = 这个作者最后一次被下载的时间。气泡**右边那颗圆形 ⟳** 是「重读抖音作品数 + 最新发布时间」，点一下绕过 6 小时缓存真查一次（转圈时不能连点）。
  · 里面那个棕色小字 `本地多 50` / 绿色 `新增 50` 是**本地和抖音的数量差**：多出来的通常是对方删了或设成私密，少了就是有还没下载的新作品。没有差值就不显示。
  · 2026-10-31 改版：这一行变回**浅灰圆角气泡**（原来是一串没有底色的文字，飘在卡片右下角），并且**去掉了「本地 xx-xx」那一项**（跟「作品数」重复），宽度只包住内容，永远右对齐。
  · 「发布」取的是**两个来源里较新的一个**：下载器作品表（`downnnnnnnn\Data\UID…_发布作品.xlsx` 的「发布时间」列）和**本地已下载作品的最新发布日期**。为什么要这样：作品表是**上次跑这个作者时的快照**，有的号一年没被跑过，表里最新还停在去年——直接显示就会出现「本地 2026-10-28，抖音却发布 2025-11-03」这种自相矛盾的画面。本地作品本来就是抖音上的作品，所以取较新的那个既不会倒挂，作品表真的更新时（说明有没下载的新作品）也能露出来。鼠标悬停会写明用的是哪个来源。
  · **打开详情页会自动联网查一次**（抖音真实接口，**6 小时内不重复查**——这道缓存现在在服务端，换浏览器、刷新页面都算数；你手点 `↻` 才会真的重查一次），查到了就优先显示它——那个日期才是抖音上真正最新一条作品的时间。日期变成**棕黄色 + 虚线下划线**时，意思是「本地还有一条更新的，但抖音主页上已经看不到它了」：多半是对方删了或者设成了私密（有的作者就是这样，本地 09-16，主页只剩 09-11）。鼠标悬停会写清楚。
- **账号状态里那条「停更/偶更」** → 原来的「停更/偶尔更」缩短成 **停更/偶更**（2026-10-31 改的，185 个账号已按新名字迁移，等级/状态/标签都不受影响）。改名前另存了 `backup\user_data.改停更状态名之前_*.json`。
- **作者等级只有 4 档** → `夯`（最高）→ `顶级` → `一般` → `拉`（最低），空着 = 未设置。同一组大小号共用一个等级（设一个人的，组里其他人跟着变）。
  · 2026-10-31 把原来的「1级（次）」「2级（拉）」改名成了「一般」「拉」——**你已经标过的等级不会丢**，当天已经按新名字迁移过一遍（22 个「一般」、8 个「拉」）。侧边栏「等级」栏、右上角筛选、导出页、详情页胶囊用的都是新名字。
  · 等级只表示**重要程度**，和更新频率无关：设等级不会再自动改频率。「作者等级」标题右边那颗小 `?` 悬停能看到这条说明。
  · 等级/频率那四颗胶囊在这一格里**均分宽度**，窗口缩放（100% / 110% / 125%）都不会有哪颗被裁掉。
  · 侧边栏「等级」那栏是**两行两列的小格子**：第一行 `夯 · 顶级`，第二行 `一般 · 拉`（每格 30px 高，比原来四行 38px 省地方）。
  · 作者信息里 `抖音号 / UID / SEC_UID` **永远排一行**：放不下时缩短 SEC_UID 的显示（仍可点开主页、悬停看完整地址），不会掉到第二行——浏览器缩放从 100% 调到 110%/125% 也不会。
- **详情页的「历史记录」在哪** → 动作栏里那颗 **时钟图标**（右上角小圆点里的数字是条数），鼠标停上去会提示「历史记录（N 条）」。点一下从按钮下方展开浮层，能看到每条「时间 / 改了什么 / 原值 → 新值」，右边 ✎ 改、× 删，最下面「＋ 手动记录」。点浮层外面或按 Esc 就收起。
  · 动作栏一共三颗**纯图标**按钮（鼠标停上去才出文字提示）：`⭐ 星标` · `📁 打开文件夹` · `🕘 历史记录`。
  · 详情页那张信息栏现在是**一行五格**：`账号状态 · 作者等级 · 更新频率 · 标签 · 备注`（从左到右）。备注压成了单行（写长了框里上下滚）。
  · 同一行里，**作者等级的四颗胶囊不带颜色**：没选是浅灰、选中是深灰，只看「选了哪个」，不再用红/紫/蓝区分；侧边栏「等级」四项也一起去掉了颜色。
  · **标签**用的是和主页作者卡一样的小粉片（浅底 + 红字 + 圆角），右边 `＋ 添加` 打开面板：上面搜索框可以打名字新建，下面列的是已有的全部标签和各自账号数，点一下就加进去；点标签上的 `×` 摘掉。
  · 「作品 / 抖音发布 / 最后下载」三串数据是作者卡**右下角的一整行**——常显，不用点也不用悬停，最右端那颗 **⟳** 才是「重读抖音作品数 + 最新发布时间」的入口：点一下绕过 6 小时缓存真查一次（约 2.8 秒），转动时不能连点。鼠标停在各段上能看到更细的来源说明。
- **想把「最新作品发布时间」批量刷一遍** → 侧边栏「功能 → 🧰 批量获取资料」，右上角有 **🕗 查发布时间**（旁边「📈 数作品」是刷作品数的，两个不一样）。
  · 点开后填数量：**建议 50~100 个**（约 3.5 秒一个，**每 25 个还会停 30 秒**，100 个 7 分钟左右），单轮最多 100，可以分几次刷完全部。按钮上出现 **⏸** 就是正在那 30 秒的空档里，不是卡死了。
  · **7 天内查过的会自动跳过**——查同一个号第二次和第 500 次对风控没区别，纯属浪费。想连刚查过的也重查，就在弹窗里填 `0`。
  · 这个走的是**登录态 + 签名接口**（会用到你下载器里的登录 cookie），比「数作品」重得多，所以节奏放慢、单轮变少；**连续 8 个查不到会自动停下**，过一会儿再点一次会接着查。
  · 跑完提示里会分开写三种「没查到」：**无公开作品 N** = 对方主页本来就没有公开作品（私密号/被封/作品全删）；**SEC_UID 失效 N** = 这个号注销或换号了，得重新补 SEC_UID；只有真被风控挡住才会算进「失败」。这三种分开算，就是为了不让你把「一批注销号」误当成「自己被限流了」。
  · 节奏对比：下载器用**同一个 cookie** 是平均 6 秒一个请求、每 10 个号停 60 秒；这里 3.5 秒一个、每 25 个停 30 秒，比下载器宽松一些。
  · 结果存在 `data\latest_work.json`，删了只是下次重新查，不影响别的东西。
- **怎么知道某个作者多久没下载过了** → 卡片上会显示 `⬇ 12 天前`（超过 30 天变橙色），详情页有「最后下载 12 天前 + 日期」。排序下拉选「最后下载」，配上「↑ 正序 / ↓ 倒序」，就能把「最久没下载」的排到最前面 —— 这批就是该重新抓的。
  · 这个数据来自我自己建的小库 `data\download_log.db`（作者 / 文件数 / 最后下载时间），不是 DouK 的下载记录。DouK 那张记录表只存作品 ID，没有作者也没有时间，查不出这种东西；而**文件的写入时间就是下载完成时间**，扫描时顺手记下来即可。这个库删了会重建（重建要跑一次全量）。
- **缓存占太大** → 双击 `clean-cache.bat`（只清缩略图和转码，封面不动），或在网页侧边栏「功能 → ⚙️ 设置」的缓存那一栏点清理。
- **双击 `start-browser.bat` 后窗口里要看什么** → 正常会依次出现「整理封面缓存...」「正在载入索引...」「索引就绪，用时 N 秒 · N 位作者（添加时间：缓存命中 N / 读盘 N 个、N 秒）」「服务已启动: http://127.0.0.1:8723/」，然后自动开浏览器。整个过程现在只要一两秒。
  · 2026-10-30 修过一次「停在『正在载入索引』半分钟不动」：为了按「添加顺序」排序，启动时要去 `E:` 机械盘读 1700 个作者文件夹的创建时间，盘休眠刚唤醒时这一串读取极慢。现在这些时间存在 `data/added_at_cache.json`，启动只读这个小文件（101 KB），只有**新下载/改名出来的新文件夹**才去读一次盘。这个文件可以删，删了下次启动会重建（重建那一趟会慢一点，之后又快）。
  · 万一以后再卡在某一行，把窗口截图发我——现在每一段都会打印耗时，能直接看出卡在哪。
- **作者列表里好多账号没有封面（变成深蓝色空块）** → 已经修好了（2026-10-30 14:40，一共 341 位）。原因是这些作者以前改过文件夹名，封面记的还是老文件夹的名字，图片找不到就显示成空块。现在按「同一个文件还在就只把文件夹名换掉，文件换了就用他最新作品的首帧」全部修好，当时那批失效封面已全部修好。

## 一条硬规矩

新增/改脚本时，路径一律 `from paths import ...`，不要再自己写 `os.path.dirname(__file__)`。
以前每个脚本各拼一遍，代码一挪目录就读不到 `data/user_data.json`，而服务会把「读不到」当成「空库」写回去——这是历史上丢数据的形态。现在 `merge_save_user_data()` 已经会在读失败时直接报错中止，但别给它这个机会。
