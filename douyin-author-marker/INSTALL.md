# 抖音作者本地库标记 · 安装与使用说明

> 一句话：刷抖音网页版时，右侧会浮出一张小卡片，告诉你**当前视频的作者，你本地存了多少作品、最后一次是什么时候下载的**。数据只从你本机的下载记录里读，不联网、不上传。

- 版本：1.4.6（本地服务 1.3.9）
- 适配：Chrome / Edge（内核 111+，2023 年后的版本都可以）
- 数据来源：`D:\ai_Project\douyin-local-library\browser\data\download_log.db` + `user_data.json`（你现有「浏览器」程序用的同一份数据）

## 一、三分钟装好

### 第 1 步：启动本地服务

**日常就用一个**：双击 `D:\ai_Project\douyin-local-library\start-all.bat`

它一次拉起两个服务，并回报是否都起来了：

```
  [1/2] 本地管理后台    http://127.0.0.1:8723
  [2/2] 插件查询服务    http://127.0.0.1:8790
  [OK] 8723 后台      ：运行中
  [OK] 8790 查询服务  ：运行中
```

只想起其中一项，就用各文件夹里原来的启动文件（它们没被改动）：

| 服务 | 单独启动 | 说明 |
| --- | --- | --- |
| 本地管理后台 8723 | `browser\start-browser.bat` | 有窗口，能看到扫描日志 |
| 插件查询服务 8790 | `local-service\start-service.bat`（有窗口）<br>`local-service\start-silent.vbs`（无窗口） | 首次建索引 1~3 秒；静默模式日志写进 `local-service\service.log` |

**一次停两个**：双击 `D:\ai_Project\douyin-local-library\stop-all.bat`。

它按端口找出两个服务并结束进程，顺手关掉 8723 那个会卡在 “Press any key” 的残留窗口，最后再验证一遍是否真的停了：

```
  [OK] 8723 后台      : 已停止
  [OK] 8790 查询服务  : 已停止
  [确认] 8723 已经关掉了
  [确认] 8790 已经关掉了
```

只想停其中一项：关掉 8723 的窗口；查询服务双击 `local-service\stop-service.bat`。

> 没有设开机自启。想让它每次开机都在，就把 `start-all.bat` 放进
> `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\`。

### 第 2 步：装扩展

**Chrome：**

1. 地址栏输入 `chrome://extensions/` 回车
2. 右上角打开「开发者模式」
3. 点「加载已解压的扩展程序」
4. 选中文件夹：`D:\ai_Project\douyin-local-library\douyin-author-marker\扩展`
5. 列表里出现「抖音作者本地库标记」即成功（建议点一下图钉，固定到工具栏）

**Edge：** 同上，地址换成 `edge://extensions/`，左下角「开发人员模式」。

### 第 3 步：验证

1. 点工具栏上的插件图标 → 应显示「**本地服务已连接**」以及作者数、文件数
2. 打开 https://www.douyin.com 任意视频
3. 右侧出现「本地库」小卡片；如果命中，作者**头像右上角**会出现一个写着数字的小圆点（本地已存多少作品）

> 首次打开抖音页面如果没反应，刷新一次页面即可（扩展只在页面加载时注入）。

## 三、它是怎么工作的（原理）

### 3.1 识别当前视频作者

抖音网页版是单页应用，作者信息有三条路可拿，按可靠性依次尝试：

| 顺序 | 来源 | 说明 |
| --- | --- | --- |
| ① | 抖音自己的接口返回 | `page-hook.js` 在页面世界旁听 `/aweme/detail` 等接口的 JSON，取出 `aweme_id` + `author.sec_uid/uid/nickname`。这是**最权威**的，和抖音自己认的是同一个人 |
| ② | 地址栏 | `/video/<作品ID>` 拿作品 ID；`/?modal_id=<作品ID>` 同样能取到（推荐流点开视频都是这种形式）；`/user/<sec_uid>` 直接就是作者主页 |
| ③ | 页面 DOM | 收集所有 `a[href*="MS4wLjAB"]`（即用户主页链接），按「离正在播放的 `<video>` 最近」挑一个，昵称取链接文字 |
| ④ | 页面文本 | 抖音短剧/合集/新版详情页会把作者名做成纯文本，按 `data-e2e="video-author-name"` 等标记取昵称，再拿昵称去本地库做精确匹配 |
| ⑤ | 页面自带的 JSON | 直接打开视频链接时，抖音是服务端渲染，接口请求发生在插件装上之前。于是到「含当前作品 ID」的那段 `<script>` 里就地找 `author.sec_uid` / `nickname` |

判定「正在播放的视频」用的是几何位置：找面积够大、在视口内、离屏幕中心最近并且 `!video.paused` 的那个元素。

**只有作品 ID、连作者是谁都不知道时**，也会把 ID 送去本地库反查——只要你以前下载过这条视频，就能认出作者。这也是 ② 里 `modal_id` 那条特别重要的原因。

**宁可认不出，也不认错。** 有一种情况特别危险：合集/短剧页拿不到作品 ID，只能借用「最近一次接口响应」的作者——那可能来自你上一个视频。所以借用之前会先在页面文字里核实这个名字真的出现了，找不到就一律显示「认不出作者」，绝不把别人的库存挂到这个视频上。

**认不出的时候**，把鼠标停在横栏上会显示诊断信息，比如：

```
识别来源：url · 作品ID 7123456789012345678
识别来源：无 · 没拿到作品ID
```

截图给我就能定位是哪一步断了。另外点「再查 / 刷新」不是拿旧结果重查，会**重新识别一次**（页面可能刚把作者名渲染出来）。

拿到之后拼成查询条件：`sec_uid`、`uid`、`nickname`、`aweme_id` 一起送到后台 → 本地服务。

#### 一个 detail 响应里到底有哪些字段可用

插件只旁听、不额外请求，所以**响应里有什么就能白拿什么**。目前在用的（打勾）和能扩展的：

| 分组 | 字段 | 含义 | 用途 |
| --- | --- | --- | --- |
| 作品 | `aweme_id` | 作品 ID | ✅ 本地精确匹配 |
| | `desc` | 文案 | ✅ 按「日期+文案前20字」对文件名 |
| | `create_time` | 发布时间 | ✅ 「发布」行 |
| | `media_type` / `images` | 视频/图文、图数 | ✅ 图文提示 |
| | `is_top` | 是否置顶 | ✅ 「本视频 · 置顶」 |
| 互动 | `statistics.digg_count` | 点赞 | ✅ |
| | `statistics.comment_count` | 评论 | ✅ |
| | `statistics.collect_count` | 收藏 | ✅ |
| | `statistics.share_count` | 分享 | ✅ |
| | `statistics.play_count` | 播放（网页端常为 0） | 空则隐藏 |
| 规格 | `video.duration` | 时长(ms) | ✅ 0:15 |
| | `video.width` / `height` | 分辨率 | ✅ 1080p（取短边） |
| | `video.play_addr.data_size` | 原片字节数 | ✅ 与本地文件比大小，小太多标 ⚠ |
| | `video.bit_rate[]` | 各档码率 | 可扩展：判断有没有更高清 |
| 音乐 | `music.title` | 音乐名 | ✅ |
| 话题 | `text_extra[].hashtag_name` | 话题标签 | ✅ 最多 4 个 |
| 地点 | `poi_info.poi_name` | 定位地点 | ✅ |
| 作者 | `author.follower_count` | 粉丝数 | ✅ |
| | `author.aweme_count` | 抖音作品数 | ✅ |
| | `author.ip_location` | IP 属地 | ✅ |
| | `author.custom_verify` | 认证信息 | ✅ |
| | `author.signature` | 签名 | ✅ 悬停显示 |
| | `author.total_favorited` | 获赞总数 | 已取到，暂未显示 |

没取、但接口里还有的：`anchors`（商品/小程序挂载）、`status.is_delete`、`aweme_control.*`（能否下载/转发）、`seo_ocr_content`（画面文字）。要加随时说。

### 3.2 和本地数据怎么匹配

本地服务里的匹配是**严格分级**的，绝不会瞎猜：

1. `sec_uid` 精确命中 → 最可信（改名也不影响，因为 sec_uid 终身不变）
2. `uid` 精确命中 → 同样可靠
3. 昵称精确命中（去首尾空格、忽略大小写）；若同一昵称对应多个账号，取「最后下载时间最近」的那个，并在卡片上提示「匹配到 N 位同名」
4. 昵称包含匹配（只命中唯一一个时才用，否则拒绝返回）
5. **只看作品 ID**（推荐流里页面没给作者时）：如果这个视频本身就在你的库里，用作品 ID 反查作者，照样能显示

匹配不上就老实返回「未收录」，不会拿相似昵称冒充。

### 3.3 数据流

```
抖音页面
  ├─ page-hook.js（页面世界）──postMessage──┐
  └─ content.js（隔离世界）识别作者 ─────────┤
                                            ▼
                              background.js（后台 Service Worker）
                                  · 内存缓存 60 秒
                                  · GET http://127.0.0.1:8790/lookup
                                            │
                                            ▼
                              bridge.py（本地只读服务）
                                  · 启动时建索引（1 秒）
                                  · 查询纯内存，~0.01 ms
                                  · 数据文件一变自动重建
```

## 四、本地数据的存储形式与字段

### 4.1 存储形式

**不新建数据库**，直接读你已有的两份数据，而且**只读打开**（SQLite 用 `mode=ro`，Python 用 `json.load`，全程不写回）：

| 文件 | 大小 | 作用 |
| --- | --- | --- |
| `browser\data\download_log.db` | ~180 MB | SQLite。全部文件的下载记录（作品数、体积、时间） |
| `browser\data\user_data.json` | ~1.1 MB | JSON。作者档案（昵称、抖音号、sec_uid、星标、状态） |

### 4.2 表结构（download_log.db）

```sql
CREATE TABLE file (
    rel        TEXT PRIMARY KEY,   -- 相对路径 "UID123_昵称_发布作品/2026-05-01-xxx.mp4"
    uid        TEXT NOT NULL,      -- 作者 UID
    folder     TEXT NOT NULL,      -- 作者文件夹名
    name       TEXT NOT NULL,      -- 文件名
    size       INTEGER DEFAULT 0,  -- 字节
    mtime      INTEGER DEFAULT 0,  -- 文件写入时间（≈ 下载完成时间），Unix 秒
    first_seen TEXT,               -- 本程序第一次看到它
    last_seen  TEXT
);

CREATE TABLE author (
    uid           TEXT PRIMARY KEY,
    folder        TEXT,
    file_count    INTEGER DEFAULT 0,
    bytes         INTEGER DEFAULT 0,
    last_download INTEGER DEFAULT 0,  -- max(mtime)
    last_scan     TEXT
);
```

`user_data.json` 的结构（节选）：

```json
{ "accounts": { "1000000000000000001": {
      "nickname": "示例昵称", "douyin_id": "example_id",
      "sec_uid": "MS4wLjABAAAA...", "starred": false,
      "status": "", "level": "夯",
      "alt_accounts": ["..."] } } }
```

### 4.3 服务对外返回的字段（`/lookup`）

| 字段 | 含义 |
| --- | --- |
| `status` | `hit` 命中 / `miss` 未收录 |
| `matched_by` | `sec_uid` / `uid` / `nickname` / `nickname_ambiguous` / `nickname_fuzzy` / `aweme` |
| `author.nickname` / `douyin_id` | 昵称、抖音号 |
| `author.file_count` / `bytes` | 已存作品数、占用空间 |
| `author.last_download` / `first_download` | 最后一次 / 第一次下载时间（Unix 秒） |
| `author.recent[]` | 最近 6 条记录（文件名 + 时间 + 大小） |
| `author.starred` / `status` | 是否星标、账号状态（注销/卖号等） |
| `video.downloaded` | 当前这个视频本身是否已在库里 |
| `meta.scanned_at` | 数据最后扫描时间（对应 `author.last_scan`） |

接口只有两个会用到的：

```
GET /health                                    服务状态与规模
GET /lookup?sec_uid=&uid=&nickname=&aweme_id=  查作者
GET /refresh                                   手动重建索引
```

## 五、界面：位置、样式、实时更新

界面有两种形态：**卡片**（看详情）和**横栏**（只占 34px 高，少挡视频）。什么时候用哪个：

| 形态 | 触发条件 |
| --- | --- |
| 卡片（276px 宽） | 命中作者、默认展开时 |
| 横栏（34px 高） | ① 点右上角 `–` 收起；② 本地库未收录；③ 认不出作者 |

### 5.1 位置与操作

- **卡片**：固定在浏览器窗口右侧（默认距右 16px、距顶 104px）。挂在独立 Shadow DOM 里，跟抖音样式完全隔离，不会被页面 CSS 搞乱，也不挤动页面布局。
- **收起成横栏**：点标题栏的 `–`，卡片变成一行 34px 高的横栏，靠边待着；点横栏任意位置（或 `⌃`）展开回卡片。
- **拖动**：按住标题栏或横栏拖到任意位置，位置会记住，下次打开还在那儿。拖完松手不会误触展开。
- **头像角标**：命中时在**作者头像右上角**压一个小圆点，里面直接写已存数量（金边深底，`pointer-events:none`，点不到、挡不住点击）。只在能认出头像时用这种形式；认不出头像就退回「昵称后面的小胶囊」。

这样布置的原因：抖音视频区、右侧评论区、底部工具栏都是它自己的布局，硬塞东西容易错位。贴在窗口边缘 + 可拖动 + 可收成横栏，既不遮挡，也能一直看见。

### 5.2 卡片内容

```
● 本地库                        ↻  –
────────────────────────────────
用户哥                    [＋待下载] [主页 ↗]
[夯] [正常] [日更] [★] [猪]      311 个 · 761 MB
粉丝 123.5 万 · 抖音作品 128 · IP 浙江
最后下载   16 小时前  10-31 21:05
✔ 本视频已存 · 10-31 17:37
抖音最新 11-01 · 本地最新 10-24 · 落后 8 天
────────────────────────────────
10-31  用户哥-没有文班比赛的日子，真的很难熬…
10-30  用户哥-纵享丝滑
10-29  用户哥-小小爵士而已，拿捏！文班加油！！
数据更新 10-31 23:21      仅本机读取
```

版式固定成两段：

- **第一行**：只有昵称，右边是 `＋待下载` 和 `主页 ↗` 两个按钮，**两个按钮永远紧挨着**（`＋待下载` 在左、`主页 ↗` 在右）
- **第二行**：**等级、状态、更新频率、星标、标签全在这行**，最右边顶格显示「N 个 · 体积」

第二行的小牌含义：

| 小牌 | 来源字段 | 示例 |
| --- | --- | --- |
| 紫色 | `level` 等级 | 夯 / 顶级 / 一般 / 拉 |
| 绿色 | `status` 账号状态 | 正常 / 停更·偶更 / 禁言·封号 / 注销 / 卖号 |
| 金色 | `update_freq` 更新频率 | 日更 / 3天更 / 周更 / 月更 |
| 灰色 `★` | `starred` 星标 | — |
| 灰底 | `tags` 标签 | 猪 / 多图 / cos（最多 6 个） |
| 灰底 `又名` | `alias` 别名 | 又名 xxx |

塞不下会自动裁掉末尾，**鼠标停在第二行**上能看到完整的「等级 · 状态 · 更新频率 · 星标 · 标签 · 别名」。

「最后下载」那行**先显示多久以前，再显示具体时间**（`16 小时前` 在前、`10-31 21:05` 在后）——一眼能判断新鲜度，需要精确值时再往右看。

**不显示抖音号**；**不再显示「本视频」那块**（发布/互动/规格/音乐都去掉了）。等级是紫色小牌（夯/顶级/一般…），状态是绿色小牌（正常/注销/卖号…）。

两个按钮：

- **`＋待下载`**：把这位作者推到管理后台的「待下载区」。库里没有这个人时，会顺手让后台**新建作者主页**并把昵称/抖音号/资料填好
- **`主页 ↗`**：直接打开管理后台里的这位作者（`http://127.0.0.1:8723/#author=<uid>`），能看/播他所有已下载的作品

还有两个只有插件能给的判断：

- **落后 N 天**：抖音上该作者最新发布日期（后台爬的 `remote_latest.json`）对比本地最新一条作品的日期；不拿下载时间比，避免被「搬家时间」带偏
- **✔ 本视频已存**：先按作品 ID 精确匹配，匹配不到再按「发布日期 + 文案前 20 字」对文件名（老文件没有 ID 也能认出来，后面会标「按文案匹配」）

**「本视频已存」只在确认是同一条视频时才说**，下面任何一条不满足就不会显示这句话：

| 条件 | 说明 |
| --- | --- |
| meta 的作品 ID 必须等于当前视频的 ID | 页面上没拿到 ID 时，插件手里那份数据可能是**别的视频**的，绝不能拿来算 |
| 文件名的日期 = 视频发布日 | 后端的硬条件 |
| 文案前 20 字至少 4 个字 | 一两个字的文案几乎能命中任何文件名 |
| 文件里写的作品 ID 必须就是这条（如果文件名里有 ID） | 老文件没写 ID 才走文案匹配 |
| 下载时间不早于发布时间 | 一分钟前才发的视频，本地不可能早就存过 |

匹配到的那条文件名会在**鼠标悬停**「✔ 本视频已存」时显示，方便核对。另外时间超过一年的会带上年份（`25-12-29 22:51`），避免和今年的 `12-29` 看混。

### 5.2b 作品卡片上的发布时间

作者主页的作品墙、以及右侧「TA 的作品」面板，每个作品**右下角**都会压一个 `10-24` 样式的时间标签（跨年份显示 `25-10-24`）。

数据来源：**页面自己发过的接口响应**（`/aweme/v1/web/aweme/post/` 等），由 `page-hook.js` 旁听拿到 `aweme_id → create_time`，再用 `aweme_id` 去匹配页面上的卡片链接。所以：

- 不额外发请求，不碰你的登录 cookie，不增加风控风险
- 平台没给（还没加载到的作品）就不显示，不会瞎猜
- 滚动加载新一页时会自动补上，最多慢 0.7 秒

### 5.3 横栏长什么样

命中后收起（一行，34px 高），右边直接带「推送下载」和「主页」：

```
● 用户哥 · 已存 311 · 最后下载 16 小时前 10-31 21:05 ✔本视频已存   ＋下载  主页 ↗   ↻ ⌄
```

未收录时自动就是这个形状，同样可以直接推送（**没下载过的作者也能推**）：

```
● 路人甲 · 本地库未收录                              ＋待下载  再查  本地库
```

认不出作者时同理，只是中间写「认不出作者」，此时「＋待下载」是灰的（没有 sec_uid/uid 推不了，点进他的主页再推即可）。

最右边的 `⌄` 是展开（点横栏任意位置也能展开，`⌄` 只是给个明确入口）。横栏宽度随内容自适应，最宽 760px，永远只占一行。

### 5.4 待下载区（在管理后台的「导出作者信息」页）

在抖音页面点卡片上的 **`＋待下载`**（收起成横栏时是 **`＋下载`**），这位作者就会出现在管理后台 → 功能 → **导出作者信息** 页面最上面的「📥 待下载区」里。

**本地库没收录的人也照样能推**——横栏上那个 `＋待下载` 就是干这个的。

- **库里没有这个人**：插件会把昵称/抖音号/sec_uid 一起送过去，后台自动**新建作者主页**（`/api/create_author` 查 UID、拉资料、写进 `user_data.json`），并标记「已新建主页」
- **库里已经有**：直接入队，标记「库里已有」
- **建档失败**（比如后台没开、cookie 过期）：照样入队，红字写出原因，你开着后台再点一次就行
- **重复点**：同一个 uid 只留一条，不会堆叠

面板上有三个按钮：

| 按钮 | 作用 |
| --- | --- |
| 预览 | 展开显示抖音号、粉丝数、sec_uid、备注等细节；再点收回去 |
| × （每行右侧，鼠标移上去才出现） | 删这一位。**会先弹一个确认框**，问你「要不要连作者主页一起删」（见下） |
| 清空 | 清空待下载区，内容先存进 undo（可撤销） |
| 取消清空 | 把刚才清空的那批原样放回来 |
| 刷新 | 手动重新读取（插件刚推过来、页面还没刷新时点一下） |

**推送时没有昵称的，会自动补上**。陌生作者推送时页面上可能还没渲染出名字，只能带着 `sec_uid` 入库；后台建档成功后，队列会用本地作者库把昵称、抖音号、等级、状态、标签补回来，所以列表里不会长期挂着一串数字 uid。

**同一个人只会有一条**。判重按 `uid` → `sec_uid` → 昵称（两个 ID 都没有时才比昵称）。建档前 uid 是空的、建档后才有值，光比 uid 会把同一个人当成两个，所以用 `sec_uid` 兜底；命中时还会把新拿到的 uid/资料补进已有那条，不会丢信息。

点队列里的任意一位，直接跳进该作者的详情页。

**删除时的确认框**

点 `×` 会弹出：

```
┌────────────────────────────────────────┐
│ 从待下载区移除「苦瓜.」？                │
│ 这位作者本地还没有作品，主页是推送时自动建的。│
│ ☑ 同时删除这位作者的主页（user_data 里的条目）│
│                        [取消] [确定移除]  │
└────────────────────────────────────────┘
```

- **本地作品数 = 0** 时才会出现这个勾选项，默认**已勾上**（推送时误加的人，主页也一起清掉最省事）；不想删就取消勾选
- **本地已经有作品**时不显示勾选项，只提示「这位作者本地还有 N 个作品，主页不会被删除」——避免手滑把有库存的作者主页删了
- 勾上后 `确定移除` 会先删主页（`POST /api/save` 里 `{accounts: {uid: null}}`），再把这个条目从待下载区移除，然后自动刷新作者列表
- 删主页失败（比如 8723 没开）不影响条目被移除，提示里会写明失败原因

「作品数」是查本地文件来的（`/queue` 返回里每条都带 `works`），不是队列里记的旧值，所以刚下载过的作者也能立刻反映出来。

### 5.5 删除作者（管理后台 · 作者详情页）

作者详情页右上角、星标/文件夹/历史记录那一排图标里，最后是一个**垃圾桶按钮**。点它：

1. 弹出确认框，写清三件事：会从作者列表移除、会自动加入黑名单、**本地已下载的文件不会被删**
2. 确认后：先写黑名单（`POST /api/blacklist`，原因记为「删除作者」），再删 `user_data.json` 里的这条主页（`POST /api/save` 传 `{accounts: {uid: null}}`）
3. 自动退回作者列表并刷新，黑名单计数同步 +1

顺序是刻意的：**先加黑名单，再加删除**。万一黑名单写失败，就整体中止、什么都不删——避免出现「主页删了但没进黑名单，下次抓取又把他捞回来」的半截状态。反过来如果黑名单成功、删主页失败，提示里会写明，你可以到黑名单页核对。

要注意的：

- **文件不动**。删除只是删「作者条目」，硬盘上的视频还在。真要删文件走「文件管理 → 回收站」那套（有二次确认和恢复）。
- 加了黑名单之后，抓「喜欢/收藏」和下载都会自动跳过这个人，想解除就去「黑名单」页面移出。
- 删除后地址栏的 `#author=<uid>` 会被清掉，刷新不会去找一个已经不存在的作者。
- **和大号小号的关系会被一并摘干净**。删掉的账号会从组内其他成员的 `alt_accounts` 里移除，如果它原本是组里的「大号」，`main_uid` 也会清掉。不做这一步的话，服务端归一化会把「还被别人引用着的空 uid」重新补成一条只有 `alt_accounts` 的空记录，页面上就会多出一个**「未命名账号」**——这个坑已经修掉了。

### 5.6 用插件推送时删主页，会加黑名单吗？

**不会**。待下载区那个删除选项只清「误加的条目 + 空主页」，不加黑名单——因为你可能只是想重新推一次，并不是以后都不要这个人。要彻底拉黑请到作者详情页用垃圾桶按钮。

队列文件在 `local-service\pending-queue.json`，**不碰管理后台的数据文件**；后台页面通过 `http://127.0.0.1:8790/queue` 读写，所以 8790 没开时会提示「未连接」+ 重试按钮。



左上角的圆点就是状态灯：**绿**=命中，**黄**=未收录，**红**=服务没开。

### 5.3 实时更新

- 每 450 ms 检查一次「当前是谁」；另有 `MutationObserver`（220 ms 节流）、`scroll`/`wheel`（160 ms 节流）、`popstate` 三重触发，切视频基本是「手一滑就变」
- 作者一换，卡片立刻重画；同一作者不重复请求（走缓存）
- 抖音是单页应用，前进/后退、从推荐流切到主页、滚动换视频，都能跟上
- 每次查询带一个序号，慢请求回来时如果用户已经切走，结果会被丢弃，不会串号

## 七、开关、刷新与缓存

**总开关**：点插件图标 → 「启用插件」。关掉后内容脚本立即停止识别、移除卡片和角标、不再发任何请求（页面不用刷新）。

**两个显示开关**：侧边卡片、昵称角标，可以单独关。

**刷新的三个层次**：

| 操作 | 作用 |
| --- | --- |
| 卡片上的 `↻` | 跳过缓存，重查当前这一个作者 |
| 弹窗「清除缓存并刷新」 | 清空后台全部缓存，并让当前标签页立即重查 |
| 本地服务 `/refresh`（或重启服务） | 重建整个索引，例如你刚批量下载完 |

**缓存策略**：

- 后台内存缓存，默认 **60 秒 TTL**，LRU 上限 500 条（超了淘汰最旧的）
- 缓存键 = `sec_uid|uid|昵称|作品ID`，所以同一个作者换视频也会重新查一次「本视频是否已下载」，但作者基础信息仍复用
- 缓存只存「查到的结果」（本来就是本机数据），不存任何页面内容
- **服务端另有一层**：`bridge.py` 每 60 秒看一眼数据文件的时间戳，一旦主程序扫描出新作品就自动重建索引，不用你手动重启

## 八、性能：数据量大也不卡

实测数据（你当前的库）：**1,723 位作者 / 323,534 个文件**。

| 环节 | 耗时 | 说明 |
| --- | --- | --- |
| 服务启动建索引 | **约 950 ms**，只做一次 | 一趟全表扫描，在内存里建 4 张表：`uid→记录`、`sec_uid→uid`、`昵称→uid`、`作品ID→(uid,时间)` |
| 单次查询 | **0.01 ms** | 纯字典命中，不碰磁盘 |
| 页面侧开销 | 可忽略 | 450 ms 一次的检测只做 `querySelectorAll('video')` 和作者链接比对，几十微秒 |
| 网络 | 本机回环，无 DNS、无 TLS | 返回体几百字节 |

对页面加载的影响：

- 内容脚本 `run_at: document_idle`，等页面基本就绪才注入，不抢首屏
- 唯一的额外请求是本地 `127.0.0.1`，不发外网
- 卡片是独立 Shadow DOM，`pointer-events:none` 包一层，不参与页面重排
- 兜底：`MutationObserver` 用 650 ms 节流，连续滚动也不会把主线程占满

即使库再大 10 倍（300 万文件），启动索引也就在 3~8 秒、内存几十 MB 的量级，查询时间不变。

## 九、隐私：只读本机，不上传

- 服务只监听 **127.0.0.1**（`bind` 写死在 `config.json`），局域网和外网都访问不到
- 扩展的 `host_permissions` 只有 `http://127.0.0.1:8790/*`，没有任何远程域名
- 扩展**没有** `tabs`、`cookies`、`webRequest`、`downloads` 等敏感权限，只有 `storage`（存开关和卡片位置）
- 不采集、不统计、不发任何埋点，没有远程代码
- 数据库以 `mode=ro` 只读打开，插件不可能改你的下载记录
- 卡片上那行「仅本机读取」就是这件事的明示

唯一会离开本机的，是抖音自己的正常页面请求——和插件无关。

## 十、常见问题

**Q：弹窗显示「本地服务未连接」**
说明 8790 端口上没有服务在跑（重启电脑后最常见）。双击 `D:\ai_Project\douyin-local-library\start-all.bat`，两个服务一起起来；只想补查询服务就双击 `local-service\start-silent.vbs`（无窗口）。起过一次之后，插件每 15 秒自动重试，服务一起来卡片自己就恢复，页面不用刷新。

**Q：怎么确认服务真的在跑**
- 插件弹窗点「测试连接」，显示「本地服务已连接 · 1.1.0」即正常
- 或者浏览器打开 http://127.0.0.1:8790/health ，能看到 JSON
- 静默模式的日志在 `local-service\service.log`

**Q：能不能开机自动启动**
没有做自启。想的话把 `start-all.bat` 的快捷方式丢进
`%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\` 即可；不想要就删掉那个快捷方式。

**Q：端口 8790 被占用**
改 `local-service\config.json` 里的 `port`（比如 8791），再在插件弹窗里把端口改成一样的，点「保存」。

**Q：横栏一直显示「认不出作者」**
多见于推荐流刚加载。滚动一下或点进视频详情页。如果一直这样，说明抖音改了 DOM 结构，需要更新扩展。

**Q：点「本地主页 ↗」是空白页**
`http://127.0.0.1:8723` 没开。双击 `start-all.bat` 或 `browser\start-browser.bat`。

**Q：作者明明存了却显示「未收录」**
1. 看是不是改过名且 `user_data.json` 没同步（本插件支持历史昵称，但需要数据里有记录）
2. 点卡片 `↻` 强刷一次
3. 本地服务窗口里看是否有 `检测到数据文件变化，重建索引` 的日志

**Q：下载时间看着不对（例如全都一样）**
`mtime` 是**文件写入时间**。如果你后来整体搬过文件夹或复制过，时间会变成搬家时间——这是文件系统的限制，不是插件算错。合并报告那次的 `18.3 GB` 移动就是这种情况。

**Q：改了数据目录**
改 `config.json` 里的 `download_db` / `user_data`（Windows 路径用 `\\` 或 `/`），重启服务。

**Q：不想要了**
1. `chrome://extensions/` 里点「移除」
2. 双击 `local-service\stop-service.bat`，关掉 8723 的窗口
3. 整个文件夹删掉即可。不写注册表、不装系统服务、不留后台进程。

## 十一、技术备注

- Manifest V3；`page-hook.js` 用 `world: "MAIN"` 注入页面世界（Chrome/Edge 111+ 支持）
- 所有对本地服务的请求都走 Service Worker 发起，绕开 https 页面对 `http://127.0.0.1` 的混合内容限制与 CORS
- 内容脚本里的状态机以「作者 + 作品 ID」为键，键不变就不重复请求
- `bridge.py` 零第三方依赖，Python 3.9+ 即可；只用 `sqlite3` / `http.server` / `json`
